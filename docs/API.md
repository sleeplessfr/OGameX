# OGameX JSON API (v1)

A machine-readable API so bots and AI agents can play OGameX without the web UI.
It runs the same game code as the web pages (resource production, queues, requirements), so the rules are identical.

Base URL: `http://<your-server>/api/v1`

## Conventions

- Requests and responses are JSON. Send `Content-Type: application/json` with POST bodies.
- Success: `{"success": true, "data": ...}`
- Error: `{"success": false, "error": {"code": "machine_readable_code", "message": "...", "details": {...}}}`
  (`details` is only present when there is something useful to say, e.g. the cost and your resources.)
- Authentication: `Authorization: Bearer ogx_...`. Get a token from register or login. Only a hash of the token is stored.
- Times are Unix timestamps in seconds. Durations are seconds. Resources are integers.
- Every authenticated call first brings the player up to date (production, finished queues, arrived fleets),
  so what you read is current.
- Coordinates: galaxy `1..<number of galaxies>` (see `/universe`), system `1..499`, planet position `1..15`.
  Position 16 exists only for expeditions.

| Status | Meaning |
|---|---|
| 200 / 201 | OK / created |
| 401 | Missing, invalid or expired token; wrong e-mail or password |
| 403 | Banned account, or registration through the API is disabled |
| 404 | Planet or queue item not found (also returned for other players' planets) |
| 422 | Invalid input, or a game rule refuses the action |
| 429 | Rate limited (Laravel's standard throttle response) |

Common error codes for 422: `validation_failed`, `unknown_object`, `wrong_object_type`, `requirements_not_met`,
`not_enough_resources`, `vacation_mode`, `shipyard_busy`, `research_in_progress`, `research_lab_upgrading`,
`character_class_required`, `build_rejected`, `research_rejected`, `invalid_coordinates`, and for fleets `unknown_ship`,
`invalid_speed`, `invalid_holding_time`, `attack_block`, `mission_rejected`, `not_recallable`; for messages `message_not_found`. A `mission_rejected` message is
the game's own reason (no free fleet slot, not enough ships or fuel, cargo too small, mission not possible there, ...).

## Settings (`.env`)

| Variable | Default | Meaning |
|---|---|---|
| `OGAMEX_API_REGISTRATION` | `true` | Allow `POST /auth/register` |
| `OGAMEX_API_TOKEN_TTL_DAYS` | `0` | Token lifetime in days, `0` = never expires |
| `OGAMEX_API_RATE_LIMIT` | `300` | Authenticated requests per minute, per account |
| `OGAMEX_API_AUTH_RATE_LIMIT` | `30` | Register/login requests per minute, per IP address |

The first account created on a fresh server becomes the admin, also through the API.

## Endpoints

### Public

| Method | Path | Description |
|---|---|---|
| GET | `/universe` | Name, number of galaxies, systems per galaxy, speeds, server time |
| POST | `/auth/register` | Body: `email`, `password`, optional `token_name`. Creates the account with its start planets and returns a token. The player name is generated by the game. |
| POST | `/auth/login` | Body: `email`, `password`, optional `token_name`. Returns a new token. |

Register and login return `data.token`, `data.token_type` (`Bearer`), `data.expires_at` and `data.user`.

### Account and overview (token required)

| Method | Path | Description |
|---|---|---|
| POST | `/auth/logout` | Revoke the token used for the call |
| GET | `/me` | Account and the IDs of its planets and moons |
| GET | `/status` | **The call to poll.** Player, every planet (resources, storage, production per hour, energy, building and unit queues), research levels and queue, fleet slots, unread message count |
| GET | `/planets` | Every planet and moon with its resources |
| GET | `/planets/{planet}` | One planet with building levels, units on it and its queues |

### Buildings

| Method | Path | Description |
|---|---|---|
| GET | `/planets/{planet}/buildings` | Every building valid here: level, cost and duration of the next level, `requirements_met`, `can_afford` |
| POST | `/planets/{planet}/buildings` | Queue an upgrade. Body: `machine_name` (e.g. `metal_mine`) or `id` |
| GET | `/planets/{planet}/buildings/queue` | The queue |
| DELETE | `/planets/{planet}/buildings/queue/{queueId}` | Cancel. A started item is refunded |

### Research

Research belongs to the player but is paid with the resources of one planet, so you choose the planet.

| Method | Path | Description |
|---|---|---|
| GET | `/planets/{planet}/research` | Every technology: level, cost and duration of the next level on this planet |
| POST | `/planets/{planet}/research` | Queue research. Body: `machine_name` (e.g. `energy_technology`) or `id` |
| GET | `/research/queue` | The research queue |
| DELETE | `/research/queue/{queueId}` | Cancel. A started item is refunded |

### Ships and defense

| Method | Path | Description |
|---|---|---|
| GET | `/planets/{planet}/units` | Every ship and defense unit: amount here, cost and seconds per unit, `max_buildable` |
| POST | `/planets/{planet}/units` | Order units. Body: `machine_name` or `id`, and `amount`. If the planet cannot pay for all of them, as many as it can afford are ordered; the response gives `requested` and `ordered` |
| GET | `/planets/{planet}/units/queue` | The queue. Unit orders cannot be cancelled |

### Galaxy

| Method | Path | Description |
|---|---|---|
| GET | `/galaxy/{galaxy}/{system}` | The 15 planet positions of a system: `null` if empty, otherwise the planet, its owner (`is_me`) and whether it has a moon |

### Fleets

Fleets are sent through the same game code as the web UI, so fuel, cargo, fleet slots, mission rules and the attack
block are exactly the game's own. Alliance combat (ACS), missiles and fleet unions are not available yet.

| Method | Path | Description |
|---|---|---|
| GET | `/ships` | Every ship with its speed, cargo capacity, fuel capacity, fuel use, attack, shield and hull, with your research applied |
| GET | `/fleet` | Your flying fleets (going out and coming back) and fleets of other players heading for your planets. Includes `fleet_slots`. Other players' fleets show where they come from and when they arrive, not what is on board |
| POST | `/planets/{planet}/fleet/check` | Dry run, nothing is sent. Same body as sending, `mission` optional. Returns, per mission, whether it is possible (and why not), plus `duration_seconds`, `deuterium_consumption`, `cargo_capacity`, `fuel_capacity`, `distance` |
| POST | `/planets/{planet}/fleet` | Send a fleet from this planet or moon |
| POST | `/fleet/{mission}/recall` | Call a flying fleet back (only your own, only before it arrives, not a return trip) |

Body of `check` and sending:

| Field | |
|---|---|
| `mission` | `attack`, `transport`, `deployment`, `espionage`, `colonisation`, `recycle`, `moon_destruction` or `expedition` |
| `galaxy`, `system`, `position` | Target. Position 16 is for expeditions |
| `type` | `planet` (default), `moon`, `debris_field` |
| `ships` | Object `{"small_cargo": 2, "espionage_probe": 1}` (machine names, see `/ships`) |
| `resources` | Optional `{"metal": 0, "crystal": 0, "deuterium": 0}` to carry along |
| `speed_percent` | Optional, 10 to 100 in steps of 5, default 100 |
| `holding_hours` | Expeditions only: 1 up to your astrophysics level |

A fleet entry has `id`, `mission`, `is_mine`, `is_return`, `from` and `to` (planet id, type, coordinates), `departure_at`,
`arrival_at`, `seconds_remaining` and, for your own fleets, `ships`, `resources` and `can_recall`.

```bash
# Can I do something at 1:2:5 with two small cargos? How long and how much fuel?
curl -s -X POST http://localhost/api/v1/planets/12/fleet/check -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"galaxy":1,"system":2,"position":5,"ships":{"small_cargo":2}}'

# Send them with 100 metal
curl -s -X POST http://localhost/api/v1/planets/12/fleet -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"mission":"transport","galaxy":1,"system":2,"position":5,"ships":{"small_cargo":2},"resources":{"metal":100}}'
```

### Messages

Spy reports and battle reports come back as structured data, so a program can act on them.

| Method | Path | Description |
|---|---|---|
| GET | `/messages` | Newest first. Query: `category` (`espionage`, `combat`, `expeditions`, `transport`, `fleet_other`, `messages`, `information`, `economy`, `universe`, `system`), `unread_only=1`, `page`, `per_page` (1-50, default 20), `mark_read=1`. Listing does not mark messages as read unless `mark_read=1` is given |
| GET | `/messages/{id}` | One message with its full plain-text body and, when it has one, `espionage_report` or `battle_report` |
| POST | `/messages/{id}/read` | Mark as read |

A message has `id`, `key`, `subject`, `body` (plain text), `viewed`, `created_at`, `has_espionage_report`, `has_battle_report`.

`espionage_report`: `target` (galaxy, system, position, type, owner_id), `player_info`, `resources`, `debris`,
`buildings`, `research`, `ships`, `defense`, `counter_espionage_chance`. How much is filled in depends on how many
probes you sent and your espionage level, as in the game. `battle_report`: `target`, `general`, `attacker`,
`defender`, `rounds` (the number of rounds, not the log), `loot`, `debris`, `repaired_defenses`, `wreckage`.

### Merchant

The resource merchant buys one resource and pays in the other two at random rates (the rates are relative to the 3:2:1 base values of metal, crystal and deuterium; about 90% of fair value on average, 70% at worst). Calling one costs dark matter (3,500) and he stays until you trade with him once or dismiss him. Same rules and code as the web UI.

| Method | Path | What it does |
|---|---|---|
| GET | `/merchant` | `dark_matter` (your balance), `call_cost`, and `merchant`: `null`, or `type` (the resource he buys) with `receive` = for each resource he pays in `rate`, `per_unit_given` (how much you get for one unit you give) and `display` |
| POST | `/merchant/call` | Body: `type` (`metal`, `crystal` or `deuterium`: what you want to sell). Costs dark matter. Returns the same data as GET, status 201. Errors: `insufficient_dark_matter`, `merchant_already_active` (trade or dismiss first), `vacation_mode` |
| POST | `/planets/{planet}/merchant/trade` | Body: `receive` (object, e.g. `{"crystal": 5000}`; only resources other than the one he buys) and `give_amount` (most you will give him). Paid from and delivered to that planet. Wishes are scaled down to fit `give_amount`, the planet's stock and free storage. One trade only, then he leaves. Returns `gave`, `received`, `dark_matter`. Errors: `no_active_merchant`, `trade_failed`, `validation_failed` |
| POST | `/merchant/dismiss` | Sends him away without trading; the dark matter is not refunded |

### Character class

Collector (mines, energy, transporters), General (combat, +2 fleet slots, Reaper) or Discoverer (-25% research time, expeditions, +10% larger colonies). The first choice is free; changing costs 500,000 dark matter and is refused while fleets are flying. Same rules and code as the web UI.

| Method | Path | What it does |
|---|---|---|
| GET | `/character-class` | `class` (`collector`, `general`, `discoverer` or `null`), `change_cost` (0 while the free choice is unused), `dark_matter`, and `options` with the bonuses of each class |
| POST | `/character-class` | Body: `class`. Returns the same data as GET. Errors: `class_change_refused` (not enough dark matter, same class, fleets flying), `validation_failed`, `vacation_mode` |

### Moons

A moon is a planet entry with `"type": "moon"` in `GET /planets`, `/status` and `/me`. It takes the normal endpoints with its own ID: `GET/POST /planets/{moon}/buildings` (lunar_base, sensor_phalanx, jump_gate, plus the usual storages and shipyard; the moon's field limit and the lunar base requirements are the game's own), `/planets/{moon}/units` and `/planets/{moon}/fleet`. Only two moon actions need their own endpoints. Both use the same services as the web UI, so range, deuterium cost and cooldowns are the game's rules.

| Method | Path | What it does |
|---|---|---|
| POST | `/planets/{moon}/phalanx` | Body: `galaxy`, `system`, `position` of a planet in range of the sensor phalanx. Costs 5,000 deuterium on the moon. Returns `fleets`: every fleet flying to that planet (and the predicted return flights of fleets that left it): `mission`, `hostile` (an enemy attack), `is_return_trip`, `origin`, `destination`, `ships`, `ship_count`, `arrival_time`, `seconds_until_arrival`. Errors: `not_a_moon`, `no_sensor_phalanx`, `out_of_range` (range is level squared minus 1 systems), `not_enough_deuterium`, `no_planet_at_target` (404), `target_is_moon`, `target_is_admin`, `target_is_own`, `validation_failed` |
| POST | `/planets/{moon}/jump-gate` | Body: `target_moon_id` (another moon of yours with a jump gate) and `ships` (e.g. `{"light_fighter": 20}`). Moves the ships at once and puts both gates on cooldown. Returns `ships` and `cooldown_seconds`. Errors: `not_a_moon`, `no_jump_gate`, `jump_gate_cooldown` and `target_cooldown` (`details.seconds_remaining`), `target_not_found` (404), `target_not_a_moon`, `target_is_source`, `target_no_jump_gate`, `ship_not_transferable`, `not_enough_ships`, `fleet_being_processed`, `vacation_mode`, `validation_failed` |

```bash
curl -s -X POST http://localhost/api/v1/planets/45/phalanx \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"galaxy":1,"system":42,"position":8}'
```

### Highscore

| Method | Path | Description |
|---|---|---|
| GET | `/highscore` | Query: `type` (`general`, `economy`, `research`, `military`; default `general`), `page`, `per_page` (1-100, default 25). Returns `players` (rank, user_id, username, score, `is_me`, `main_planet` coordinates, alliance_tag, total_ships for military), `total_players`, `total_pages`, and `me` with your rank and score in all four rankings. The game caches the ranking for a few minutes |

## Queue items

Queue lists show the item being worked on first (`active: true`), then the waiting items. `seconds_remaining`
and `duration_seconds` are `0` while an item is still waiting for its turn. Buildings and research add
`target_level`; unit orders add `amount`, `amount_remaining`, `seconds_until_next_unit` and `seconds_per_unit`.

## Example

```bash
# Create an account and keep the token
curl -s -X POST http://localhost/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"agent1@example.com","password":"a-strong-password","token_name":"agent1"}'

# Look at the state of the game
curl -s http://localhost/api/v1/status -H "Authorization: Bearer $TOKEN"

# Queue a metal mine on planet 12
curl -s -X POST http://localhost/api/v1/planets/12/buildings \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"machine_name":"metal_mine"}'
```

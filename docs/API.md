# OGameX JSON API (v1)

A machine-readable API so bots and AI agents can play OGameX without the web UI.
It runs the same game code as the web pages (resource production, queues, requirements), so the rules are identical.

Base URL: `http://<your-server>/api/v1`

## Conventions

- Requests and responses are JSON. Send `Content-Type: application/json` with POST bodies.
- Success: `{"success": true, "data": ...}`
- Error: `{"success": false, "error": {"code": "machine_readable_code", "message": "...", "details": {...}}}`
  (`details` is only present when there is something useful to say, e.g. the cost and your resources.)
- Authentication: `Authorization: Bearer ogx_...`. Get a token from register or login. Only a hash of the token is stored.
- Times are Unix timestamps in seconds. Durations are seconds. Resources are integers.
- Every authenticated call first brings the player up to date (production, finished queues, arrived fleets),
  so what you read is current.
- Coordinates: galaxy `1..<number of galaxies>` (see `/universe`), system `1..499`, planet position `1..15`.
  Position 16 exists only for expeditions.

| Status | Meaning |
|---|---|
| 200 / 201 | OK / created |
| 401 | Missing, invalid or expired token; wrong e-mail or password |
| 403 | Banned account, or registration through the API is disabled |
| 404 | Planet or queue item not found (also returned for other players' planets) |
| 422 | Invalid input, or a game rule refuses the action |
| 429 | Rate limited (Laravel's standard throttle response) |

Common error codes for 422: `validation_failed`, `unknown_object`, `wrong_object_type`, `requirements_not_met`,
`not_enough_resources`, `vacation_mode`, `shipyard_busy`, `research_in_progress`, `research_lab_upgrading`,
`character_class_required`, `build_rejected`, `research_rejected`, `invalid_coordinates`.

## Settings (`.env`)

| Variable | Default | Meaning |
|---|---|---|
| `OGAMEX_API_REGISTRATION` | `true` | Allow `POST /auth/register` |
| `OGAMEX_API_TOKEN_TTL_DAYS` | `0` | Token lifetime in days, `0` = never expires |
| `OGAMEX_API_RATE_LIMIT` | `300` | Authenticated requests per minute, per account |
| `OGAMEX_API_AUTH_RATE_LIMIT` | `30` | Register/login requests per minute, per IP address |

The first account created on a fresh server becomes the admin, also through the API.

## Endpoints

### Public

| Method | Path | Description |
|---|---|---|
| GET | `/universe` | Name, number of galaxies, systems per galaxy, speeds, server time |
| POST | `/auth/register` | Body: `email`, `password`, optional `token_name`. Creates the account with its start planets and returns a token. The player name is generated by the game. |
| POST | `/auth/login` | Body: `email`, `password`, optional `token_name`. Returns a new token. |

Register and login return `data.token`, `data.token_type` (`Bearer`), `data.expires_at` and `data.user`.

### Account and overview (token required)

| Method | Path | Description |
|---|---|---|
| POST | `/auth/logout` | Revoke the token used for the call |
| GET | `/me` | Account and the IDs of its planets and moons |
| GET | `/status` | **The call to poll.** Player, every planet (resources, storage, production per hour, energy, building and unit queues), research levels and queue, fleet slots, unread message count |
| GET | `/planets` | Every planet and moon with its resources |
| GET | `/planets/{planet}` | One planet with building levels, units on it and its queues |

### Buildings

| Method | Path | Description |
|---|---|---|
| GET | `/planets/{planet}/buildings` | Every building valid here: level, cost and duration of the next level, `requirements_met`, `can_afford` |
| POST | `/planets/{planet}/buildings` | Queue an upgrade. Body: `machine_name` (e.g. `metal_mine`) or `id` |
| GET | `/planets/{planet}/buildings/queue` | The queue |
| DELETE | `/planets/{planet}/buildings/queue/{queueId}` | Cancel. A started item is refunded |

### Research

Research belongs to the player but is paid with the resources of one planet, so you choose the planet.

| Method | Path | Description |
|---|---|---|
| GET | `/planets/{planet}/research` | Every technology: level, cost and duration of the next level on this planet |
| POST | `/planets/{planet}/research` | Queue research. Body: `machine_name` (e.g. `energy_technology`) or `id` |
| GET | `/research/queue` | The research queue |
| DELETE | `/research/queue/{queueId}` | Cancel. A started item is refunded |

### Ships and defense

| Method | Path | Description |
|---|---|---|
| GET | `/planets/{planet}/units` | Every ship and defense unit: amount here, cost and seconds per unit, `max_buildable` |
| POST | `/planets/{planet}/units` | Order units. Body: `machine_name` or `id`, and `amount`. If the planet cannot pay for all of them, as many as it can afford are ordered; the response gives `requested` and `ordered` |
| GET | `/planets/{planet}/units/queue` | The queue. Unit orders cannot be cancelled |

### Galaxy

| Method | Path | Description |
|---|---|---|
| GET | `/galaxy/{galaxy}/{system}` | The 15 planet positions of a system: `null` if empty, otherwise the planet, its owner (`is_me`) and whether it has a moon |

## Queue items

Queue lists show the item being worked on first (`active: true`), then the waiting items. `seconds_remaining`
and `duration_seconds` are `0` while an item is still waiting for its turn. Buildings and research add
`target_level`; unit orders add `amount`, `amount_remaining`, `seconds_until_next_unit` and `seconds_per_unit`.

## Example

```bash
# Create an account and keep the token
curl -s -X POST http://localhost/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"agent1@example.com","password":"a-strong-password","token_name":"agent1"}'

# Look at the state of the game
curl -s http://localhost/api/v1/status -H "Authorization: Bearer $TOKEN"

# Queue a metal mine on planet 12
curl -s -X POST http://localhost/api/v1/planets/12/buildings \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"machine_name":"metal_mine"}'
```

## Not available yet

Fleets (send, recall, list), messages, highscore, battle simulation, custom player names, and the other
parts of the game (alliances, merchant, moon buildings' special actions, planet management).
